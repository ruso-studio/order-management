Order entry maintenance notes
============================

Scope
-----
- Frontend: index.html, styles.css, app.js.
- Bilingual message parsing: utils/orderParser.js.
- Order/sheet schema reference: utils/orderFieldConfig.js.
- Google Apps Script: apps-script/Code.gs; matching schema reference: apps-script/sheetConfig.gs.
- Separate status lookup scraper: server.js and utils/steadfast_scrapper.js. It is not part of order entry or courier creation.

Google Sheet
------------
- Order tab: Current. Rows 5–500. Column C (Product) determines whether a row is occupied.
- A:L: Name | Mobile | Product | Unit price | ID | Delivery charge | Extra cost (If any) | Parcel ID | Selling price | Profit | Steadfast link | Status.
- J (Profit) and K (Steadfast link) are formulas. Apps Script writes A:I and L only.
- IDs increment for Direct and Online orders using the greatest numeric ID in E5:E500. A custom Order ID overrides generation and is also the Steadfast invoice.
- A blank product is stored as `Unspecified product` to preserve the column C occupancy marker.
- Price list: `Price chart!A4:B100` (product name and unit price); cached only in browser memory until refreshed.

Order behavior
--------------
- The order type switch supports Online and Direct; pasted message text detects type automatically. English and Bengali labels are parsed.
- Direct blank customer name becomes `Direct sell`. Model matching is exact (case-insensitive); a selected catalog item populates its unit price.
- Online orders may create a parcel. The browser calls `POST https://portal.packzy.com/api/v1/create_order` with `Api-Key`, `Secret-Key`, and `Content-Type: application/json` headers.
- Payload keys follow Steadfast's guide: invoice, recipient_name, recipient_phone, recipient_address, cod_amount, and item_description. COD amount is the entered selling price; delivery charge is not added.
- Credentials are read first from `cred.js` (`api_creds.apiKey`, `api_creds.apiSecret`); Settings session values are fallback credentials. Since `cred.js` ships to the browser, its keys are visible to app users. Direct browser calls require Steadfast to allow the GitHub Pages origin via CORS.
- Item description contains the order message fields and COD amount (selling price plus delivery charge), including the address; it excludes unit price. Note is optional and sent as the Steadfast `note` field.
- Order IDs are generated as `ORD-1001`, `ORD-1002`, etc., continuing from the highest numeric or `ORD-` ID in rows with a product in column C. The next order is written below the last row with a product in column C, even if there are gaps between earlier orders.
- After Apps Script saves an order and returns its row/ID, the app makes the Steadfast call. On success it posts the returned consignment ID to H and status to L via `action: updateParcel` (using `Pending` if Steadfast omits the status); J/K formulas are not altered. A confirmation modal shows the returned consignment ID, tracking code, and tracking link.
- If courier creation fails after order save, the order stays saved and the app reports the parcel error.

Apps Script deployment
----------------------
- Deploy apps-script/Code.gs as a Web App, Execute as: Me, access: Anyone. `app.js` contains the deployed `/exec` URL.
- Apps Script reads `Price chart` and writes `Current`; there is no order-entry trigger and no Steadfast request in Apps Script.
- After code changes, deploy a new Web App version using Manage deployments.

Steadfast credentials
---------------------
- Enter API Key and Secret Key using the app Settings button. The values stay in current-browser sessionStorage.
- Do not copy credentials into published source, Apps Script, or the checked-in notes. `steadfast api doc.txt` is ignored by Git because it contains credentials.
- Parcel creation does not use the Node/Render service. That service remains for the separate status lookup/scraper.
